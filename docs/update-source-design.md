# 更新源协议

客户端支持官方 GitHub Releases、直接 HTTPS 签名清单和备用镜像。源码、程序、更新清单使用公开读取，客户端不使用个人 GitHub 凭据。

## 信任与清单

JSON 签名信封包含 `keyId`、Base64 `payload` 和 `signature`。先用客户端内置 ECDSA P-256 公钥验证原始载荷字节和 SHA256 签名，再解析载荷。

载荷字段为 `schemaVersion: 1`、`product: CgDesk`、`channel: stable/beta`、语义化 `version`、`publishedAt`、`releaseNotes` 和 `packages`。每个包包含 `rid`、`minWindowsBuild`、`size`、`sha256` 及按优先级排列的 `urls`，最多四个镜像。当前唯一分发架构是 win-x64。

客户端检查产品、协议、通道、架构、系统构建下限和已见最高版本；稳定通道拒绝预发布版本。清单最大 256 KiB，GitHub 发布元数据最大 1 MiB，包声明大小最大 1 GiB。版本按语义化规则比较，不能按字符串字典序比较。

## 网络和下载

清单失败或超时后尝试备用源，错误信息仅包含主机与原因，不回显路径、查询参数、账户信息或服务器错误正文。拒绝 HTTP 降级、含账户信息和显式内网/本机 IP 的地址；不替代服务端域名及 DNS 管理。

稳定通道将 GitHub 仓库地址转换为 latest/download 签名附件直链，避开 REST API 匿名额度。测试通道保留发布列表 API，依据 X-RateLimit-Remaining、X-RateLimit-Reset 和 Retry-After 判断 403/429 限流，显示重试时间，保存自动检查计划，并在内存中禁止恢复时间前重复访问 API；限流不阻止尝试备用源。

下载使用唯一临时文件，限制头响应与流空闲时间，支持取消，逐块计算 SHA256。只有大小和摘要匹配后才原子移入版本化 ZIP 路径；失败和取消会清理临时文件。缓存包复用前重新校验。

主备镜像可以复制同一份签名文件，不得自行替换信任公钥。HTTPS 保护传输，签名确认发布者，SHA256 检查包内容。域名迁移可通过设置更换地址，公钥轮换需要受信任的新客户端。

## 安装边界

当前实现检测、提醒和校验下载，安装由用户手动解压，不自动关闭游戏、解压或执行下载内容。后续安装器还需单独设计文件占用处理、ZIP 路径验证、事务替换和失败回滚。

操作及发布命令见[发布说明](update-publishing.md)。
