# 0.1.12：4:3 分辨率与 FSR 窗口缩放

启动分辨率只提供 4:3，最高 1600×1200，并按当前显示器的宽、高筛选。1920×1080 显示器最高可选 1440×1080。实验默认关闭，启用前保留检测和账号风险提示；原 EXE 与资源文件不改写。

启动后按实际客户区匹配窗口台。再次拖动或最大化时，游戏绘制尺寸保持启动档位，外部窗口采集使用 FSR 等比显示，居中留边。放大走 EASU+RCAS，缩小走线性采样+RCAS。恢复了 FSR 所需着色器和 Vortice 依赖，没有恢复旧增强注入器、锐化设置或画质增强开关。采集失败恢复原生嵌入。

1280×960 及以上档位启用四个 64×64 地图缓存，以解决旧 1920×1080 试验暴露的角落覆盖不足。所有运行时指令改动均有版本字节守卫；初始化失败只有确认完整回退后才继续原生初始化。局部扫描通过旧布局 scratch 保持原来的读取、调用次数和请求矩形；没有修改服务端、协议或资源半径。详细证据和静态分析边界见 [缓存审计](map-cache-64-audit-2026-11-06.md)。

缩小时，较大的源窗口移到虚拟屏幕边缘外，仅保留 1 像素以使 Windows 持续绘制。独立 WPF 测试能持续采集完整图像，用户本机 DirectDraw 游戏测试亦报告正常。
