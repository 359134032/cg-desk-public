# 画质增强下的中文输入修复

开启画质增强后，游戏采集源位于窗口台后方，键盘由 GameHost 转发。原来只转发普通键盘消息，WPF 逻辑焦点也未确保落到原生宿主 HWND；中文输入法无法在这个路径里完成组词和提交。

现在点击增强区域或切换主窗口时同时设置原生输入焦点，并为宿主关联当前线程的默认 IME 上下文。组词消息由宿主的默认窗口过程处理，VK_PROCESSKEY 和组词期间的选字按键不转发给游戏。确认后的 WM_IME_CHAR 转为 Unicode WM_CHAR，通过显式 PostMessageW 交给目标窗口，让 Windows 为 ANSI 游戏转换字符编码。切换目标时取消未确认的组词。

增加了独立 ANSI 输入线程的回归，检查原生焦点、IME 上下文、选字回车隔离、中文编码与单次提交、英文输入和切换时的清理；FSR 回归增加原生焦点以及向独立进程提交中文的检查。键盘测试使用正确的按键释放标志；FSR 普通按键测试使用功能键，避免当前中文输入模式把测试字母作为拼音处理。窗口还原检查比较实际原始屏幕坐标，以适应高 DPI 桌面。

验证命令：

```powershell
dotnet run --project tests/CgDesk.Regression/CgDesk.Regression.csproj -c Release -- --probe-ime
dotnet run --project tests/CgDesk.Regression/CgDesk.Regression.csproj -c Release -- --probe-fsr
dotnet run --project tests/CgDesk.Regression/CgDesk.Regression.csproj -c Release
```

画面采集检查需要正常交互桌面权限。受限环境中 Windows Graphics Capture 返回 CreateForWindow 参数错误；相同程序在正常桌面权限下可完成采集和 FSR 检查。

本机结果：输入专项 12 项通过，FSR 专项通过，完整回归 175 项通过；Windows x64 自包含发布成功。构建时 NuGet 漏洞数据服务不可达产生 NU1900 警告，编译无错误。

上述输入检查模拟 IME 的组词及提交消息，不替代真实游戏配合实际中文输入法的人工验收。仍需在真实游戏聊天框确认候选窗、选字、连续中英文输入和多窗口切换。
