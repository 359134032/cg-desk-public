# 1920×1080 隔离验证

用户要求验证 1080p，只有可行时才将最大分辨率设到该档位。实验继续遵守：原 EXE 和资源文件不改写，不修改服务器、网络协议或此前无改善的角色资源刷新半径。

## 结果

1920×1080 的独立 DirectDraw7/Direct3D7 RGB 设备创建、绘制和释放通过；包含该模式的 1723 项 UI 几何和接口检查、21 个普通导出转发检查通过。窗口台独立夹具证明 1920×1080 原生客户区可保留完整尺寸，窗口台外框仍限制在当前显示器工作区；28 项分辨率相关检查通过。

随后只放开精确 1920×1080 进行真实游戏隔离试验，没有扩大缓存数组或枚举数量。用户通过官方登录器进入地图，明确反馈：“能进入，但上方角落缺图或黑块”。因此启动成功不等于可用验收通过，本轮不能将 1080p 作为可用上限。用户反馈后游戏已经关闭，未取得独立运行时宽高采样；安装 INI 和用户报告不能伪装成内存测量。

## 缓存分析

地图范围由 `0x4a0540` 固定为 X[-30,+21)、Y[-20,+31)，每轴最多 51 格。读图和绘制证据分别为 `ev_9511a3c603cd4d1be65d956d7e59b6bf0f17bfabefd5ba81dde94db0ef2449eb`、`ev_6e47bee0af5084243f2f8f45f549709ce0516682e69d93f25cdaed5b0111c594` 和 `ev_2288448764ad1e951a5e5b32229d81f9a60aa51ead043653ba32e1859a01c831`。

实际投影为 sx=32(dx+dy)+centerX，sy=24(dy-dx)+centerY；镜头为 W/2,H/2。对应证据为 `ev_d49bdf0894bb510f52385dbc6f30b91d1c9e3ee85ec5b9cc95528e08fbda8d78` 和 `ev_5d8de1267b07dddefc02d6062fdff2ebc627ec2982ee38c8f30c6b71e5817f46`。1080p 上左角需要 Y 约 -26.25，上右角需要 X 约 +26.25，超出两条短边，预计上方两角缺地图锚点；用户反馈与此吻合。

绘制仍按固定缓存行列数枚举，屏幕宽高用于裁剪，因此现有代码证据不支持“只改分辨率必然使缓存索引越界”。真实缺陷是覆盖不足。若要扩充，三个地图层和碰撞缓存的固定地址、0x1452 字节清零长度、取图、碰撞及地图更新写回均须同步适配；不能仅增大取图矩形常量。相关证据包括读图 `ev_97def0421be44013f6d991c8dad9d4939673d7520b5a941f82672aeeba92261e`、碰撞构建 `ev_68a1c1176573e1e0ba3a87811a063e5d69dc70e7ea98798285c68fad3c4ce320`、替代碰撞路径 `ev_3570b28aae6beee03a38d8c1b85e1fbcccf6e0b4ce16dffa548ade9c04c92efd`、更新写回 `ev_70b8f5020195f3e6924ba7a95b330f14f962dc772efaf472030c445d831fa008`。

## 已回退

游戏退出后按哈希记录撤下两份 1080p 自有 DLL 及其 INI，恢复用户此前实测通过的固定 1024×768 V2.1 UI 修复 DLL。代理哈希恢复为 `353c3924a718132c3f2aabb59436929bb29414d9faece58912f7edac88e406c6`；原 EXE 哈希仍为 `9baa0d2660f96c6699ccf42ad46bd918717b98ccb228f4edde2d92afb89d3126`，1080p INI 已确认移除。

源码取消临时 1080p 许可，启动器仍保留原九个实验档位，1080p 不开放。保留独立 1080p 图形和窗口布局夹具供以后缓存适配使用；没有发布或替换 0.1.11 安装包。试验 DLL、安装记录与输出保存在本机被忽略的 artifacts 目录，后续不能将本次失败验收当作 1080p 已支持。
