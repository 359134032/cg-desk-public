# 64×64 地图缓存适配：静态审计及离线验证

本组件可作为待游戏验收的实验适配接入，不能据离线测试宣称 1600×1200 游戏运行已验收。全部研究使用已经提供的本地代码捕获；未运行 `partial-image.exe`，未执行其中任何指令，未附加游戏进程，未写游戏安装目录。原 EXE、资源文件及绘制/人物队列容量均未改动。

## 目标与边界

原地图四层缓存各为 51×51×2 字节。旧覆盖为玩家 X `[-30,+21)`、Y `[-20,+31)`；地图边缘会裁剪实际宽高。提案为四个独立 64×64×2 字节缓存，覆盖 X `[-36,+28)`、Y `[-28,+36)`。静态投影 `sx=32(dx+dy)+cx, sy=24(dy-dx)+cy` 下，1600×1200 最远屏幕角约需每轴 ±25 格，较短边保留约 3 格。此结论仅说明平面几何覆盖，不证明所有高大地物、实体或游戏地图效果。

`3W+4H<=7296` 是旧缓存短边留一格余量的保守限制，不是引擎已经证明的固有最大分辨率。服务器角色可见范围没有扩大。

## 保持原请求扫描语义

`0x49ab80` 含四个地图层内地址，按旧缓存位置扫描四侧各 23 格并产生最多两个请求矩形；不能只对它们加固定偏移或把入口比较的 51 改成 64。离线反例：200×200 地图、玩家 `(30,80)`，旧缓存完整 51 列，新缓存被左边界裁成 58 列；固定 `+0x40c` 会访问错误世界格子。

实现采用两个调用点 facade：

1. 全部十个 `0x4a0540` 直接调用改指向 bounds facade。先调用原函数一次，保留其原来四次保护坐标读取并保存六个旧字段；随后按已裁剪结果扩展 `xmin−6,xmax+7,ymin−8,ymax+5` 并重新夹取地图边界。原函数中的四个偏移常量保持原值。
2. 全部三个 `0x49ab80` 直接调用改指向 legacy scan facade。按实际旧/新起点差从新 layer2 拷贝原子矩形到独立旧布局 scratch；短暂恢复六个旧字段并调用原扫描函数。四个原内部读点指向 scratch 的原 `+0x26/+0x52` 偏移。`__finally` 无论正常返回或原扫描发生 SEH 都恢复六个新字段。

原扫描的 51 格入口条件、23 格扫描长度、两矩形限制、坐标保护读取次数、矩形夹取逻辑及调用方发送流程保持原代码。该替换通过全字节守卫确认相关原函数及保护整数辅助函数版本。源头 `0x49e7e0` 的后续请求发送未改。

原扫描仅调用四个保护整数操作及 `0x49ab30` 矩形夹取。前者最终进入 CRT 的线程局部随机数状态；正常路径未发现 UI 消息泵、游戏回调或地图消费重入。网络解析 `0x54c6f0→0x5426c0→0x4880b0` 与移动链 `0x49e7e0→0x49e280→0x556be0→0x557c00` 归于同一帧主循环。此为静态调用链事实，不是本轮运行时线程观测。

## 清零长度与栈安全

五个 clear CALL 原目标均为标准 x86 cdecl `0x57e7c0`，参数 `(dest, int fill, size_t count)`，返回 `dest`，由调用者清栈。包装器仅当目的地址恰好为四个新缓存之一且原长度为 5202 时，将长度改为 8192。包装器参数均为调用局部值，不使用共享参数 scratch，因此其他线程的无关 clear 维持原参数。

不能全局把读图函数的 5202 改为 8192：`0x49dac0` 会把约 5204 字节的三个栈数组传给同一读图函数。其唯一直接调用者 `0x549c20` 接收协议解析器传来的九个字段；该矩形不从新的六个全局边界字段读取，适配没有扩大此栈路径的矩形。协议本身对输入尺寸是否另有约束未由本轮证明；原代码既有尺寸假设保持原状。

## 引用范围与守卫

`AuditMapCache.py` 以 SHA-256 绑定原捕获：

- partial-image: `b95fdfaa61520908ed1a7b04fe75c74decb53a96860d17f25b8aef8a6a2b2636`
- runtime .text: `1e7f13e748c792586c7db2eb21d26d19f710bafecea02df6c2d6e44ad136d427`

`.text` 的 73 个原始范围内 u32 候选中，42 个真实操作数与 REA xrefs、指令反汇编一致；其余 31 个是指令字节巧合。42 个包括 38 个层基址和 4 个 scratch 内部地址。加上 5 clear CALL、10 bounds CALL、3 scan CALL，共 60 个四字节操作数。完整地址、原值、原始指令、字节及候选分类见 `artifacts/viewport-research/map-cache-audit-plan.json`；构建守卫位于生成的 `MapCacheProfile.h`。

四层原基址分别为 `0xa547f8/0xa55c50/0xa570a8/0xa58500`。`.rdata` 未发现落入这些缓存范围的 u32。其他原始打包段有 14 个候选：`.text1` 的 8 个解码为分支或相对 CALL 的指令字节巧合，`.pdata` 的 6 个为不透明打包数据。本地全部原始段未发现 `0x4a0540/0x49ab80` 的绝对地址字面量；捕获的 xrefs 全为上述直接 CALL。

限制：本轮运行时捕获只有 `.text`，虚拟 `.data` 无原始内容。不能仅靠它排除未捕获的动态指针表、计算地址或其他线程的间接消费。因此报告不标记引用在所有运行时状态下完整，也不标记 deployment_ready。

## 初始化事务和接入约束

公开接口：`ValidateMapCacheFix / ApplyMapCacheFix / RollbackMapCacheFix / GetMapCacheDiagnostics`。

调用方必须在已验证的游戏窗口线程、原始图形上下文尚未初始化的阶段调用 Apply；OwnerThread 绑定该线程。现有启动组件的 GameWindow/current-thread 验证可满足这一约束。建议在所需宽高、派生字段、SetWindowPos 及 client size 均成功之后、对外标记 profile applied 之前接入。旧小档可以继续使用旧缓存。

Apply 只修改代码操作数，不写六个地图边界；预检拒绝时没有缓存布局/边界改变。所有代码编辑前验证整份 profile，分配四缓存及独立 scratch，模块 pin，然后逐页临时改保护、写入、FlushInstructionCache、恢复准确原保护。每个新缓存的第 8192 字节之后是未提交的 guard page。原函数及容量限制保持原状。

初始化失败时恢复原代码及页保护；Apply 返回 false 后仍应调用 Rollback，并确认它返回 true 且 ProtectionRestored=1。如果恢复失败、初始化时有意外缓存使用或状态无法确认，保留内存不释放，并返回失败；调用方必须停止这次启动，不能仅恢复宽高后继续转发。模块 pin 是有意保留到进程退出的组件生命周期约束。

一旦任何新缓存 hook 真正使用过，公开 Rollback 拒绝任意热回退；应重启进程。扫描 facade 拒绝非 OwnerThread 或重入调用，在这种拒绝前不触碰临时六字段。Clear 包装器支持任意线程且只识别精确新目的地址。若真实游戏诊断出现 ThreadOrReentryRejected，应视为静态线程假设被反证，停止此实验档。

## 离线验证结果

`Test-MapCache.ps1` 同时以 MSVC x86 `/W4 /WX /O2` 编译测试 host 和无测试宏的生产 object。Host 只把捕获 PE 作为 SEC_IMAGE 数据映射；调用的是 host 自己的 synthetic callbacks，绝不调用捕获中的游戏指令。

2666 个地图尺寸/玩家边界场景，116233 项检查，0 失败。覆盖：

- 60 处操作数修改、1/30/60 处部分写入故障、完整原字节及所有页保护恢复、错版本及卸载映像拒绝。
- 新 bounds 与直接目标公式逐项相等；原 bounds/scan 各只调用一次。
- scratch 全矩形与原世界格子逐项相同，四侧 23 格扫描路径一致。
- 原扫描 SEH 的 finally 恢复、同线程重入拒绝、其他线程拒绝。
- 新缓存完整清零、其他长度保持、5204 栈式缓冲的后两字节保留、两线程 clear 参数互不污染。
- 新缓存 guard page、运行后热回退拒绝、初始化回退完整恢复。

2026-11-06，接入当前构建后，用户按 1600×1200 地图角落、走动切图、UI 与 FSR 缩放验收请求反馈「效果一切正常」。本机这次人工验收已通过；战斗等未单独报告的场景、所有地图、多窗口长期运行及其他版本仍无覆盖结论。角色下发范围没有作扩大保证。
