# 0.1.14：修复高分辨率传送后整屏花屏

1600×1200 下使用传送石后，部分转场特效会让地图、文字和菜单一起花掉，声音及输入仍有反应；独立游戏窗口同样受影响。原因是部分逐行特效仍使用1024行数组，高度1200时数组相互覆盖，并写入相邻特效状态。

大于1023像素高度时，独立组件改用三组互不重叠的运行时缓冲，保留转场逻辑及尺寸。140处完整指令检查后才安装，失败停止实验启动并回退部分写入；不改写原EXE或资源。4:3、1600×1200上限、默认开启、风险确认和窗口FSR缩放保持原行为。不扩大服务器角色下发范围。

用户在同一传送石连续复测后确认「不花屏了」。自身进程诊断日志也显示地图更新与绘制恢复，未观察到纹理上传失败。此验收仅覆盖本机本次场景，不保证所有特效或其他客户端版本。

已知限制：部分外围NPC、路灯靠近才出现仍未解决。已核查本地地图生成、实体缓存及最终绘制层，未找到证据充分的安全补丁；队列容量是待观察候选，未据此盲目扩大缓冲。本版不包含NPC提前刷新改动，也不将其全部归因于服务端。

核查后另按要求完成本地队列扩容试验，实机确认「无花屏，但也没有任何改善」。已撤下扩容、关闭诊断，保留已验收的转场修复；正式包不含这组无改善的实验。

离线检查：25122项转场缓冲与逐个部分写入回退检查、14组独立初始化模型、1524项几何/COM检查及47项分辨率/安装检查通过，原生导出转发与非目标程序保护通过。独立导出的正式源码构建后，正常Windows桌面完整回归223项通过，包含真实FSR GPU像素、1600×1200缩放、输入及退出恢复。沙箱隔离桌面的窗口采集返回E_INVALIDARG，正常桌面复测通过；未将隔离环境结果当作产品修复证据。原始游戏捕获、日志、账号配置及签名私钥不进入仓库或发布包。
